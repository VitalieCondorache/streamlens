How it works

Four moving parts, one goal: watch a real Kafka topic from a browser without pretending the browser can speak Kafka.

Topology

  1. Kafka 4.1 (KRaft) docker compose, one node, topics declared by the BFF
  2. → consume · produce
  3. Node BFF kafkajs · admin API · SSE fan-out · traffic generator
  4. → Server-Sent Events
  5. Angular 22 signals store · virtual list · hand-rolled murmur2

A browser cannot open a Kafka connection: the protocol is binary over TCP and Kafka's security model assumes trusted clients. So the browser talks HTTP and the BFF owns the consumer groups.

Decisions

SSE instead of WebSocket
The flow is strictly server → browser, so a unidirectional stream is enough. It survives proxies, and EventSource reconnects on its own.
Consumer group per browser session
The group id is streamlens-ui-<sessionId>, stored in localStorage. Committed offsets are the resume point: a page refresh continues where the last one stopped, with no custom bookkeeping.
Deduplication by watermark, not by hope
At-least-once delivery means a reconnect can re-deliver records. The client keeps the highest offset per partition, counts the duplicates it drops and the gaps it finds, and shows both.
Batching + real backpressure
The BFF flushes frames every 120 ms and pauses its consumer when res.write() reports a full socket, resuming on drain. In the browser, frames are coalesced per animation frame.
Rewinding is an offset rewrite
"Replay the last N records" is setOffsets on the session's group, then a reconnect. No history is kept in the frontend to fake it.
Recorded fallback
When no BFF is reachable the app replays a session captured from a real broker (npm run capture), so the deployed demo runs without infrastructure while still showing genuine records, keys and partitions.

Where to look

Running it

# 1. broker (Kafka, KRaft single node) and the BFF
docker compose up -d

# 2. the Angular app, proxying /api to the BFF
npm install && npm start        # http://localhost:4200

# optional: re-record the offline fixture from live traffic
cd bff && npm run capture

Tests: npm test (Vitest) covers the murmur2 vectors, the watermark deduplication, the statistics and the frame batcher. npm run test:e2e drives the built bundle in a real browser with no backend — lazy routes, virtual list, theme and WCAG checks. Against infrastructure: cd bff && npm run smoke for the broker pairing and npm run routes:smoke for every HTTP route.
